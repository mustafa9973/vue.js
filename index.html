⚡ Revolutionary Reactive Props Destructuring

One of the most requested features in Vue.js history has finally arrived. Vue 3.5 includes stable reactive props destructuring and memory optimizations for improved app performance.

Before Vue 3.5: Props Reactivity Issues

❌ Problem: Destructuring props in Vue 3.4 and earlier would break reactivity, forcing developers to use verbose syntax or workarounds like toRefs(). 
<!-- Vue 3.4 and earlier - Lost reactivity when destructuring -->
<script setup>
import { watch } from 'vue'

const props = defineProps({
  user: Object,
  count: Number,
  isActive: Boolean
})

// ❌ This breaks reactivity!
const { user, count, isActive } = props

// ❌ Watcher won't trigger on prop changes
watch(count, (newCount) => {
  console.log('Count changed:', newCount) // Won't work!
})

// ✅ Had to use props.count everywhere
watch(() => props.count, (newCount) => {
  console.log('Count changed:', newCount) // This works
})
</script>

Vue 3.5: Stable Reactive Props Destructuring

✅ Solution: Vue 3.5 now maintains full reactivity when destructuring props, making code cleaner and more intuitive. 
<!-- Vue 3.5 - Reactive destructuring that actually works! -->
<script setup>
import { watch, computed } from 'vue'

const props = defineProps({
  user: Object,
  count: Number,
  isActive: Boolean
})

// ✅ Now maintains full reactivity!
const { user, count, isActive } = props

// ✅ Watchers work perfectly with destructured props
watch(count, (newCount) => {
  console.log('Count changed:', newCount) // Works perfectly!
})

// ✅ Computed properties with destructured props
const computedUserInfo = computed(() => {
  return user ? `${user.name} (${user.email})` : 'No user'
})
</script>

<template>
  <div>
    <!-- ✅ Fully reactive and clean -->
    <p>Count: {{ count }}</p>
    <p>User: {{ computedUserInfo }}</p>
    <p>Active: {{ isActive ? 'Yes' : 'No' }}</p>
  </div>
</template>

Before Vue 3.5: Eager Hydration Issues

<!-- Vue 3.4 - All components hydrated immediately -->
<template>
  <div>
    <!-- Heavy component that hydrates immediately -->
    <HeavyChart :data="chartData" />
    
    <!-- Modal that might never be opened -->
    <ExpensiveModal v-if="showModal" />
    
    <!-- Below-fold component -->
    <ComplexDataTable :items="tableData" />
  </div>
</template>

Vue 3.5: Smart Lazy Hydration

<!-- Vue 3.5 - Intelligent lazy hydration -->
<template>
  <div>
    <!-- Hydrate when user scrolls near -->
    <HeavyChart 
      :data="chartData" 
      v-lazy-hydration="{  
        when: 'visible',
        rootMargin: '100px'
      }" 
    />
    
    <!-- Hydrate only when modal opens -->
    <ExpensiveModal 
      v-if="showModal"
      v-lazy-hydration="{ when: 'interaction' }"
    />
    
    <!-- Hydrate when user scrolls to it -->
    <ComplexDataTable 
      :items="tableData"
      v-lazy-hydration="{ 
        when: 'visible',
        threshold: 0.1
      }"
    />
  </div>
</template>

🔧 New Composition API Features

useId() Composable

💡 New Feature: Vue 3.5 introduces the useId() composable for generating unique IDs that work perfectly with SSR and accessibility requirements. 
<!-- Vue 3.5 - Built-in unique ID generation -->
<script setup>
import { useId, ref } from 'vue'

// ✅ Generate unique IDs for accessibility
const formId = useId()
const emailFieldId = useId()
const passwordFieldId = useId()
const errorId = useId()

const email = ref('')
const password = ref('')
const error = ref('')
</script>

<template>
  <form :id="formId" @submit.prevent="handleSubmit">
    <div class="field">
      <label :for="emailFieldId">Email Address</label>
      <input 
        :id="emailFieldId"
        v-model="email"
        type="email"
        :aria-describedby="error ? errorId : undefined"
      />
    </div>
    
    <div 
      v-if="error" 
      :id="errorId"
      role="alert"
      class="error"
    >
      {{ error }}
    </div>
  </form>
</template>

Enhanced defineExpose and unref

<!-- Vue 3.5 - Improved component exposure -->
<script setup>
import { ref, unref, defineExpose } from 'vue'

const count = ref(0)
const input = ref(null)

// ✅ Enhanced defineExpose with better TypeScript support
defineExpose({
  count,
  increment: () => count.value++,
  focusInput: () => input.value?.focus(),
  
  // ✅ Use unref for flexible value handling
  reset: (initialValue = 0) => {
    count.value = unref(initialValue)
  }
})
</script>

Enhanced Error Handling

<!-- Vue 3.5 - Better error boundaries and handling -->
<script setup>
import { ref, onErrorCaptured } from 'vue'

const error = ref(null)

// ✅ Improved error capture with better debugging info
onErrorCaptured((err, instance, info) => {
  console.error('Component error:', {
    error: err,
    component: instance,
    errorInfo: info,
    // Vue 3.5 provides more context
    componentStack: instance?.$?.vnode,
    propsData: instance?.$?.props
  })
  
  error.value = err
  return false // Prevent propagation
})
</script>

💡 Best Practices and Patterns

Reactive Props Destructuring Patterns

✅ Best Practice: Use destructuring patterns that make your code more readable while maintaining reactivity. 
<!-- Best practices for props destructuring -->
<script setup>
// ✅ Good: Simple destructuring
const { title, content, isVisible } = defineProps({
  title: String,
  content: String,
  isVisible: Boolean
})

// ✅ Good: With defaults
const { 
  theme = 'light',
  size = 'medium',
  disabled = false 
} = defineProps({
  theme: String,
  size: String, 
  disabled: Boolean
})

// ✅ Good: Complex destructuring with validation
const {
  user = {},
  settings = {},
  permissions = []
} = defineProps({
  user: {
    type: Object,
    default: () => ({}),
    validator: (user) => user && typeof user.id !== 'undefined'
  },
  settings: {
    type: Object,
    default: () => ({})
  },
  permissions: {
    type: Array,
    default: () => []
  }
})
</script>
